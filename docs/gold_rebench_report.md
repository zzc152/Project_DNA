## 2. ⚠️ 关键方法学发现：题面构造漂移

对比基线（130 条）与 final（129 条）时发现：**两者不是同一套题**。

原因：`l3_benchmark_v2.py` 中 `build_questions` 的 qtype 分配为

```python
qtype = "rc" if idx % 2 == 0 else "know"   # idx = 全量 L3 列表索引
```

final 删掉 3 条 L3（DELCAND：L3_002_2/26/29）后，全量列表索引整体偏移 → 同一 id 的题被构造为相反 qtype（rc↔know，21 条），且 `rng` 消费序列变化导致选项 flip 漂移（12 条 gold 未变但 acc 翻转）。L1/L2 同理：KB 删 3 条后 `rng.sample` 抽样集合变化。

**因此 130 vs 129 的全量对比混入了题面变化，不能归因于 gold 修复**。正确做法是"同题面配对"（§3）。

| overclaim | 12 | 13 | 12 | 13 |

**逐题结果**：74 条中 **73 条分数完全不变**（0 分差），唯一变化是 **L3_002_37**：

```
L3_002_37 [同题面] gold A→D | 模型答 A→A | acc 60→0 | total 100→40 （两模型一致）
```

- 该题 gold 从 A（增强）修正为 D（方向不明）。
- 模型始终答 A（增强）。旧 gold 下"答对"得 100 分 → 新 gold 下暴露为错误，得 40 分。
- **这恰好是 gold 修复的价值证明**：旧 gold 标注错误时模型"答对"是假高分（蒙对错误标注）；修复后模型在该题的真实表现被正确度量。

## 4. 核心结论

1. **gold 修复对模型分数影响极小**：干净配对 74+98 条中，除 2 条被修复的题（L3_002_37、L2_0007）外全部零变化或微变。修复改变的是"正确标注本身"，而非模型能力。

2. **低分≠数据差（直接证据）**：
   - **正样本 L2_0007**：旧 gold 错标 A，模型答 B 被判错（40 分）；修复为 B 后模型答对（100/80 分）——**修复前模型在这道题上的"低分"确实是数据错误所致**。
   - **反样本 L3_002_37**：旧 gold 错标 A，模型答 A 得假高分 100 分；修复为 D 后模型现出原形（40 分）——说明**修复前的部分高分也是数据错误造成的假象**。
   - 两者合在一起证明：**修复前的分数既可能低估（标注错→答对判错）也可能高估（标注错→答错判对）模型**；修复后的分数才是模型真实水平的无偏度量。

3. **修复后模型真实水平**（final 全量）：
   - L3：32B avg 64.6 / acc 0.318；7B avg 63.0 / acc 0.326。know 型 acc 仍仅 0.081（两模型一致）——不给摘要时模型依然无法判断方向（蒙 A 幻觉被平衡机制持续暴露）。
   - L1/L2：acc 3-11%，接近随机。知识回忆能力依旧薄弱，与修复前结论一致。
   - 诚实性：两模型 final 的 confident_acc 均 ≥ 0.586（32B）/0.575（7B），overclaim 下降（32B 32→29、7B 35→31），诚实分机制运行正常。

4. **题面漂移是评测脚本的设计缺陷（后续需修）**：`qtype = idx % 2` 使题面构造耦合于数据集合的增删——任何一条数据删除都会导致 rc/know 全局翻转。建议改为**基于 id 的确定性哈希**分配 qtype（如 `hash(id) % 2`），使题面只依赖单条记录、与数据集合无关，保证评测可复现、可增量对比。

## 5. 复现方式

```bash
# 三卡并行评测（final 数据，4 轮：L3/L12 × 32B/7B）
bash scripts/run_eval_final.sh

# 合并 + 评分（脚本内自动完成）
cat tmp/l3_final_32b_w{0,1,2}.jsonl > tmp/l3_final_32b_merged.jsonl
python src/data_synthesis/l3_benchmark_v2.py \
  --drafts data/synthetic/drafts_full2_clean_final.jsonl \
  --score-only tmp/l3_final_32b_merged.jsonl --out tmp/l3_final_32b_scores.jsonl

# 对比分析
python scripts/compare_eval_final.py
```

产物：`tmp/l3_final_{32b,7b}_{w0,w1,w2,merged,scores}.jsonl`、`tmp/l12_final_{32b,7b}_{...}.jsonl`、`tmp/eval_final_master.log`
